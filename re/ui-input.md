# 전장 입력 흐름

전장 창 처리기(0x40ee?? 안의 메시지 switch)가 마우스 좌표를 확대 1 픽셀(칩 24 × 12)로 바꿔 넘긴다: 이동 0x40f231 → 0x403d7b, 왼쪽 누름 0x40f2a5 → 0x403fb0, 오른쪽 누름 0x40f315 → 0x4045ee, 커서 모양(WM_SETCURSOR) 0x40f195 → 0x403d04: 단계 3이면 마우스 쪽 방향(0x4033ee, 차례 유닛이 선 자리)의 커서 0x503df4[방향](리소스 0x69·0x6a·0x6c·0x6b·0x6d·0x6e, 0x44dd9f LoadCursorA), 단계 6이면 0x503e0c(0x75), 아니면 화살표(IDC_ARROW). 커서는 RT_GROUP_CURSOR → RT_CURSOR(핫스폿 u16 x, y + DIB) 32 × 32 흑백이고, 마우스가 움직일 때와 팝업·대화 상자가 생기거나 사라질 때(Windows가 마우스 이동을 보냄) 다시 고른다. 명령 확정(0x406d13 → 0x40484b(0)) 뒤 연출 동안은 단계 0이라 화살표(`cursorShape`, `src/formats/cursors.ts`). 입력 단계는 0x476af4이고, 0x40484b(단계)가 앞 단계를 정리(0x4052b8)한 뒤 진입 함수 표 0x45e244[단계]를 부른다.

## 칸 판정

0x4034e0(x, y): 지형 종류(부품 +0x62)가 0x10·0xa·0xb가 아니면 칸으로 친다.

- 0x4031c5(px, py) → 칸(x, y) 또는 (−1, −1): 화면 칩 줄을 위에서 아래로 훑는 지형 목록(0x43be78)과 같은 차례로 칸 줄을 내려가며, 칸 높이(부품 +0x60)와 칩 안 위치(경사 = 칩 x % 24 / 3)로 고른다. 0x4034e0(x, y)가 칸이 맞는지 본다.
- 0x4033ee(px, py, x, y) → 방향 0~5: 칸 (x, y)의 중심(칩 x = (y & 1) + 1 + 2x, 픽셀 y = (2y + 24 − 높이)·12 − 16)에서 좌우와 기울기 1/3 두 선으로 나눈다.

## 명령 메뉴 (객체 0x4800d4, 0x41a3ad)

항목 4개(대기, 공격, 마법, 소환), 항목 칸 (−7, 16 + 29i)~(0x45, 42 + 29i). 켬 여부: 대기는 늘, 공격·마법·소환은 서 있는 칸에 멈출 수 있을 때(0x473fa0[이동 타입 × 0x11 + 지형])만, 공격은 공격 행동을 쓸 수 있을 때(0x410f40), 마법은 마법 하나라도 쓸 수 있을 때, 소환은 마스터이고 진영 유닛이 25보다 적을 때. 마법은 유닛 +0xc 목록, 소환은 진영 레코드 +0x38 목록을 하위 메뉴로. 고르면 0x405c4f(항목, 행동)로 0x45e298[항목]을 다음 대기 루프에서 부른다.

| 항목 | 함수 | 하는 일 |
|---|---|---|
| 0 | 0x405c74 | 이동 취소 |
| 1 | 0x405ce3 | 대기: 0x406cd2(0, 0) = 0x406d13(0, 0, 지금 칸) |
| 2 | 0x405cfe | 공격: 행동 = 유닛 +8 → 0x405d18 |
| 3 | 0x405d18 | 마법: MP < 행동 표 +0 이면 알림(0x419baa), 범위 종류 4면 중심 = 지금 칸으로 단계 6, 5면 바로 실행(0x406cd2(1, 행동)), 아니면 단계 4 |
| 4 | 0x405dcc | 소환: MP < 소환 MP(네이티얼 표 +0)면 알림, 아니면 단계 5 |
| 5~13 | 0x405e4b… | 유닛 정보 메뉴 항목(범위 보기, 0x405f5a 정보 창 등) |

명령의 방향은 실행할 때 차례 유닛 위치 객체의 방향(걷기가 마지막 걸음 방향으로 두고, 단계 3에서 마우스로 바꿈)이다.

## 유닛 메뉴 (단계 7, 객체 0x4800d8, 0x41a88e)

240 × 156 그림(DATA00 4번)에 항목 10개, 2열 × 5줄: 항목 i 칸 (⌊i/5⌋·0x78 − 7, 16 + 29·(i % 5))~(⌊i/5⌋·0x78 + 0x6d, 42 + 29·(i % 5)). 이름(exe 0x46005c~): Moving range, Attack range, Magic range, Magic+Effect, Detail Info, Effect range, Move+Attack, Move+Magic, All area, Destruction. 켬(0x404c02): [1, 1, 마법 있음, 효과 반경 마법 있음, 1, 1, 1, 마법 있음, 효과 반경 마법 있음, 되돌리기]. 마법 있음 = 사거리(행동 표 +9)가 0이 아닌 마법(0x4115dc). 되돌리기 = 고른 유닛이 차례 유닛 진영이고 그 진영 제어 0, 고른 유닛이 마스터가 아니고 차례 유닛이 마스터. 항목 0~8은 0x45e298[5~13](범위 보기 단계 8~0x14, 정보 창 0x405f5a), 항목 9는 확인 대화 상자 0x74 뒤 0x45e298[14] = 0x405f13(되돌리기: 0x406d13(3, 0, 고른 유닛 칸)). 오른쪽 클릭은 0x45e298[15] = 0x405e1d(단계 1).


## 범위 보기 (단계 8~0x14, `rangeView.ts`, 픽스처 `test/golden/rangeView.json`)

유닛 메뉴 항목 → 단계(효과음 1): 0 Moving range 8, 1 Attack range 9, 2 Magic range 0xa, 3 Magic+Effect 0xb, 5 Effect range 0xf, 6 Move+Attack 0xc, 7 Move+Magic 0xd, 8 All area 0xe. 진입 함수(0x45e244)는 범위 표식 0x4058b6(모양 1~8), 커서 켬(0x403b10), 어둡게 할 칸, 도움말 문구 0x424fed. 단계 8은 단계 2와 같은 0x4048a7(고른 유닛이 차례 유닛이면 차례 표식을 지움).

- 어둡게 할 칸: 모두 어둡게(0x43d3a6) 한 뒤 되돌리고(0x43d3fd), 끝에 어두운 칸 위 유닛을 어둡게(0x411849). 마법은 범위 종류 5를 뺀다.
  - 0x411a79(유닛, 행동, 효과): 범위 종류 4는 자기 칸(효과면 자기 칸 둘레 0x410d77). 그 밖은 효과 반경(효과가 아니면 0)이 0이면 사거리(0x41074b), 1이면 사거리 안 칸과 그 이웃 여섯 중 효과 범위, **2 이상이면 아무 칸도 되돌리지 않는다**(원작 그대로).
  - 9 0x411d9f(공격), 0xa 0x411dc5(마법), 0xb 0x411e2a(마법 + 효과).
  - 이동 결합 0x411e8f: 이동 범위(0x4404c9)에서 멈출 칸(0x440ba9)이면서 이동 타입이 멈출 수 있는 지형(0x473fa0)인 칸마다 위치 객체를 옮겨 0x411a79. 0xc 0x411fbf(공격), 0xd 0x411ff1(마법), 0xe 0x412062(마법 + 효과), 0xf 0x4120d3(마법 + 효과, 공격 + 효과).
  - 0x10 0x412247(look): 선 칸에서 사거리 안이고 그 칸을 중심으로 look이 효과 범위인 칸(범위 종류 4면 자기 칸).
  - 0x11 0x4125bd(aim): 멈출 칸에 옮겨 서면 공격 사거리에 aim이 드는 칸. 0x12·0x14 0x4051f3: 사거리 마법(0x4115dc)이 있으면 0x4125f7(aim, 마법마다 같은 식), 없으면 0x4122b2(look). 0x13 0x4051aa → 0x4122b2(look).
  - 0x4122b2: 0x411ff1로 보인 칸 가운데, 효과 반경 > 0인 마법의 중심으로 삼으면 look이 효과 범위에 드는 칸.
- 단계 7 진입(0x404c02): 고른 유닛이 차례 유닛이면 차례 표식을 지우고(0x40583f, 범위 보기에서도 다시 생기지 않음), 커서 끔, 범위 표식 0, 팝업(0x419a11), 고른 유닛 설명(0x424ed3). 단계 1에서 유닛을 오른쪽 누르면(0x4045ee 1) 그 위치 객체를 0x476b90에 둔다.
- 가상 배치: 단계 8에서 아무 칸이나 누르면 되돌리기(0x405bb2) 뒤 0x405a6e — 누른 칸이 원래 칸(0x476b90)이 아니면 원래 칸에 위치 객체 사본(가림 무늬 +0x10 = 4, +0x13 = 4)을 두고(0x476b08), 누른 칸의 다른 유닛은 숨기고(+0x13 | 2, 0x476b38), 고른 유닛의 위치 객체를 누른 칸으로 옮긴 뒤 단계 7. 범위 보기(0x4404c9·0x41074b 등)는 위치 객체를 읽으므로 옮긴 자리에서 센다. 0x405bb2는 0x476b90으로 되돌리고 사본을 지운다(0x405e1d 단계 7 → 1, 0x406573, 0x406d13).
- 왼쪽 누름(0x403fb0, 효과음 4): 8은 아무 칸 → 가상 배치 뒤 단계 7. 보이는 칸만: 0xb → 0x10(사거리 마법이 있을 때, look), 0xc → 0x11(aim), 0xd → 0x12(aim), 0xe → 0x13(사거리 마법) 또는 0x14(look), 0x13 → 0x14(aim). 0x11·0x12·0x14는 본 유닛이 차례 유닛이고 진영 제어 0이며 가상 배치가 없으면(0x476b08 = 0) 그 칸으로 걷고(0x476b10 = 지금 단계, 0x406c5b → 0x405fba), 이동 취소(0x405c74)는 0x476b10 단계로 돌아간다. 9·0xa·0xf·0x10은 없음.
- 오른쪽 누름(0x4045ee, 효과음 2): 8~0xf → 7, 0x10 → 0xb, 0x11 → 0xc, 0x12 → 0xd, 0x13 → 0xe, 0x14 → 사거리 마법이 있으면 0x13, 없으면 0xe.
- 0x476b88·0x476b18은 bss이고 차례를 넘어 남는다. 0x4051f3의 사거리 마법 없는 갈래(0x4122b2(0x476b88))는 UI로는 닿지 않는다(0xd 항목은 사거리 마법이 있을 때만 켜지고, 0xe → 0x14는 0x476b88을 먼저 쓴다).
- Detail Info(항목 4, 대화 상자 0x7f·0x80)는 ③b-4a.

## 화면 표시

- 커서(표시 객체 0x476ac0, 0x4021ee: 페이지 0x2c6, 묶음 1, 종류 0, 들림 0xc, 플래그 6으로 시작): 칸 0x476b78·0x476b7c, 켬 0x476bac(0x403b10). 자세 = 13 + 커서 프레임(0x476ad4, 0~4, 2틱마다). 켜져 있고 커서 프레임 < 2면 그 칸 지형 칩 +0x400(어두운 판), 그 칸 유닛(종류 1·6)은 색 바꿈 선택 +1.
- 차례 표식(0x476b58, 0x40574a): 차례 유닛 칸, 정렬 키 1, 페이지 0x2c6, 진영 제어 2면 자세 6·묶음 4·종류 4, 아니면 자세 0·묶음 2·종류 3. 차례 유닛은 종류 6, 플래그 | 8(덧그림 끔).
- 범위 표식(0x476aec, 0x4058b6(종류)): 고른 유닛 칸, 정렬 키 2, 페이지 0x2c6, 묶음 3, 종류 5, 자세 = 범위 종류별(0: 8·묶음 2·종류 3, 1: 0, 2: 3, 3: 6, 4: 9, 5: 12, 6: 15, 7: 0·묶음 4, 8: 3·묶음 4).
- 어둡게 할 칸(0x48e664[32][32]): 범위를 보일 때 0x43d3a6이 모두 1로 두고 범위 안 칸만 0x43d3fd로 0으로 돌린다(0x43d354는 모두 0). 1인 칸의 지형 칩 +0x400(exe 0x473534 표로 어둡게 한 판). 범위 판정: 이동 0x4404c9 → 멈출 수 있는 칸(0x440ba9 = 그래프 +0x12 & 8), 공격·마법 0x411625(칸이 맞고(0x4034e0) 사거리 0x41074b), 소환 0x4127bb(거리 1 + 0x4126d7), 효과 0x41173b(0x410d77).
- 어둡게 할 유닛: 공격·마법 범위(효과 반경 0이면 대상이 아닌 유닛 0x410e3d), 효과 범위(범위 밖 유닛)에서 위치 객체 +0xf | 1(색 바꿈 선택표 → 표 1 = 어두운 판). 0x412670이 모두 지운다.
- 커서·표식 그림: DATA00 8번을 페이지 0x2c6에(0x422f9a). 사람 차례 시작(0x40546d)마다 다시 읽는다(CPU 생각이 그 자리를 작업 버퍼로 쓴다).
- 상태 줄 문구 0x424fed. 효과음 0x443d19(번호): 1 고름, 2 취소, 4 이동 고름.

## 타이머

대기 루프 0x44db4f가 메시지가 없을 때 0x44e9b1로 16ms 단위 카운터(0x503de8)를 줄이고, 0이면 3으로 두고 0x403020을 부른다: 48ms마다 한 틱(re/rendering.md 타이머).

## 차례 시작과 대화 상자

- 차례 진행(0x40536c)이 커서 칸을 차례 유닛 칸으로 두고(0x403c8e), 화면 이동 연출(0x4147b3 → 0x4165bb)을 건다: 목표 = 표시 객체 칩 ((칩x + 1)·24, (칩y − 2)·12)를 창 가운데로(전장 안으로 자름), 단계마다 가로 먼저 최대 48px, 다 맞으면 세로.
- 입력 시작(0x40546d → 0x4055cf): CPU면 차례 표식(0x40574a)을 보이고 단계 0으로 생각(0x445b20). 사람이면 어두운 팔레트(0x4027e3), 소리 5, 자유 모드는 시간 제한 없음(모드 셀 3), 커서·표식 그림 다시 읽기(0x422f9a), 단계 1.
- 어두운 팔레트(0x4027e3): 0x76~0xe5번 = 6~0x75번 색을 채널마다 (v − 20)/3(20 미만 0). 어느 팔레트 자료도 이 칸을 채우지 않아 처음엔 검정이고, 입력 시작·범위 보이기(0x43d3a6)·유닛 메뉴 닫기(0x405e1d)에서 지금 시각 팔레트로 다시 계산한다. 어두운 칩(0x473534 표)만 쓴다.

## 전투 끝·알림판·결과 창(③b-4d, `notice.ts`·`resultWindow.ts`, 해독 메모 notes_result.md, 픽스처 `notice.json`·`resultWindow.json`)

- 끝(0x401ec3): 마스터가 쓰러진 진영의 네이티얼이 다 사라진 뒤. 승자 −1은 "You have come to a confrontation."이다. 그 밖에는 이름을 쓸 진영(승자가 사람이면 승자, 아니고 진 쪽이 사람이면 진 쪽, 둘 다 CPU면 승자)으로 "%s has\xa1\xa1%sed"(Won/Lost, 원작 철자 "Woned"·"Losted")를 쓴다. 이김(0x476b6c)은 그 진영이 승자인지이고, BGM 2 이김·3 짐이다(③b-5).
- 항복(0x9c82 → 0x401d5b): MessageBox "Is it okay to surrender?"(Confirm, 예/아니오, 답과 상관없이 소리 1). 항복 진영(0x401df5)은 사람 진영이고, 둘이면 차례 유닛 진영이다. 문구는 "<항복 진영> has surrendered", 승자는 다른 진영이다.
- 알림판(0x42e090·0x42e38f·0x42e186):
  - 폭은 ((바이트 수 + 1) >> 1) × 16 + 0x50, 높이 60이고 프레임 가운데에 뜬다.
  - 공통 그림 칩 테두리(0x1026~0x1048)를 쓰고, 글자는 그림자 (41, 23) 색 10 뒤 본문 (40, 22) 색 0xb다.
  - 0.96초 뒤 누르거나 28.8초가 지나면 닫힌다. 그동안 전투 48ms 콜백이 멈추고 효과음은 없다.
  - 물이 돌아옴(0x4022d7 끝)도 같은 알림판 "Water level has returned."이다.
- 글꼴 0x424707은 0x80 이상 바이트를 2바이트 글자(16px)로 다룬다. 글리프는 TextOutA로 32 × 24 1비트 DIB에 그려 줄마다 굵게(오른쪽 칸이 켜지고 왼쪽 칸이 꺼진 칸을 켬) 한 16 × 16을 캐시한다(0x4241ae). 영문판은 Arial이고, 한국어판은 "돋움체" 16 × 8(0x422d4d)에 같은 굵게 변환(0x422f40)이다. 24 × 12 글꼴(모드 1, 0x42416f)은 고르는 곳이 없다. 이식은 캔버스 글리프(`src/i18n/hangul.ts`)를 그린다: 한국어는 CP949(`setHangul`), 원문은 Shift-JIS(`setWideGlyphs`, 장 사이 장면 일본어), 한 글자로 풀리지 않는 쌍(영문 글의 `\xa1\xa1`·`\xa1\xa4`)은 빈칸이고 시험(오라클 대역)은 제공자가 없어 모두 빈칸이다. 원문 모드에서 사용자가 친 Latin-1 이름(é 뒤 소문자 등)은 Shift-JIS 한자로 보인다(원작 영문판은 서양 Windows에서 Latin-1로 보였음, 장면 일본어를 보이는 대가로 받아들임).
- 결과 창(0x407d43):
  - MDI 자식이고 시스템 메뉴가 없어 아이콘·닫기 단추가 없다. 608 × 420이고 클라이언트 가운데에 놓인다(x는 0 아래로 자르지 않는다).
  - 그 전에 전장·정보·미니맵 창을 닫고 도움말 문구를 비운다(0x401bd8(0)).
  - 팔레트는 공통 리소스 1·2 + DATA00 0x21(118~228번)이고, 바탕 0x22·0x23에 + 0x6f를 한다. 단추 칩 0x16은 투명 자리를 바탕으로 미리 채운다.
  - 마스터 그림은 진영 0이 페이지 0x2c6·묶음 6, 1이 0x2e4·묶음 7이고, 자세는 이긴 진영 8, 그 밖 9다.
  - 쪽: 0 요약(경과 일·시·분, 진영마다 마정석·Used MP·행동·소환·경향 %), 1·3 네이티얼(times·SAT·Ave, 목록에 없으면 색 0x79), 2·4 마법.
  - 단추: Prev는 0쪽에 없다. Next는 마지막 쪽이면 END다. 마우스 위는 노랑, 프레임은 96ms마다 넘어간다. 누르면 소리 1이고, END·Turn of World Map·Turn to Title은 월드(지금은 시작 화면)로 간다.

## 이어 하기(③b-4e, `continueData.ts`·`saveStore.ts`, 해독 메모 notes_save.md, 픽스처 `continue.json`)

  - Save는 슬롯 대화 상자 0x76 "Countinue Data"(저장 모드)를 거친다. 쓰면 결과 창 없이 전투가 끝나고, Cancel·쓰기 실패("Writing failed.")면 전투로 돌아간다.
- 저장 0x441e36: 유닛 압축(0x4071ea = `encodeState`), 창 위치(0x441960: 창이 있을 때만 바깥 사각형을 MDI 클라이언트 좌표로, 블록 +0x268~+0x2d3), 블록 +0 = 슬롯 식별값, 그다음 0x44147f(체크섬·뒤섞기)다.
- 슬롯 대화 상자 0x76:
  - 처음엔 고른 칸이 없다. 고른 칸 없이 OK면 소리 3이다.
  - 저장 모드는 빈 칸도 OK이고 두 번 누름을 무시한다.
  - 읽기 모드는 빈 칸 OK가 소리 3이고 두 번 누름이 OK다.
- 목록 줄 0x44161a: `"%s %s %4d/%2d/%2d %2d:%02d"`(구분 "F ", 마스터 종류 이름 `"%-12s VS %-12s       %-20s"`·맵 이름, 파일 마지막 쓴 시각)이다. 식별값이 다르면 대시 줄이다. 넘치면 76자로 자른다.
- 슬롯 식별값(레지스트리 System Flags): 처음은 시드 1의 rand 8개다. 읽으면 그 슬롯이 새 rand가 되어 목록에서 무효가 된다("The continue data is erased when loaded", 0x442098).
- 자동 저장 SV080(식별값 1): 사람·CPU 모든 차례, 지형 효과를 준 직후(0x40546d → 0x442045)에 쓴다. 되살린 첫 차례(+0x2dc = 1)는 쓰지 않는다. 전투가 어떻게 끝나든(0x401bd8) 지운다. 앱을 열 때 남아 있으면 "Found trace of system closed \nduring battle.\nDo you wish to play this battle again?"를 묻고, 예면 되살리고(지우지 않음) 아니오면 지운다.
- 되살리기 0x401899·0x401b12:
  - 블록 상태와 창 자리·켬·확대를 그대로 쓴다.
  - 차례 진행은 같은 유닛을 경과 0으로 다시 뽑고, +0x2dc = 1이라 지형 효과가 없다(TS `startTurn`).
  - AI 기억은 처음 값(`initialMemory`)이다.
- 저장소: `vmv2/SAVE/SV100.DAT` 등에 {원작 파일 바이트 base64, 쓴 시각}, `vmv2/System Flags`에 식별값 8개를 둔다.

## 생각 시간 제한(③b-4c-1b, `timeLimit.ts`, 해독 메모 notes_world §5.5, 픽스처 `timeLimit.json`)

- 시간 제한은 블록 +0x14(`GameState.timeLimit`)다. 진영마다 남은 연장 횟수는 +0xe64(`timeExtensions`)이고, 전투 시작 때 0x45e108[시간 제한] = 1·3·5·0이다.
- 사람 입력 시작(0x4055cf)에 타이머를 켠다. 제한은 마스터 30·60·120초, 네이티얼 15·30·60초다. 남은 시간 R은 1/6초 단위이고 벽시계(timeGetTime)로 잰다.
- 틱(0x407926): 48ms 콜백은 p = 입력 단계 ≠ 0, 걷기 끝은 p = 1로 부른다.
  - R이 바뀌면 경고음이 한 틱에 하나만 난다. 10초에 10, 3·2·1초에 11이다.
  - 다 쓰면 연장 n = ⌊(e − L × 6) / 연장 초⌋ + 1을 쓴다(소리 12, 정보 창 전체). 남은 연장보다 많으면 0이 된다.
  - R = 0이고 p ≠ 0이면 소리 13 뒤 강제 Stand by(0x406cd2 → 0x406d13, 차례 유닛 칸)다. 걷는 중이면 걷기가 끝난 새 칸에서 Stand by이고 단계 3으로 가지 않는다.
- 명령(0x406d13)·전투 시작·되살리기가 타이머를 끈다. 모달 상자·알림판 동안은 틱이 없지만 시계는 흐르므로, 닫은 뒤 첫 틱에 한꺼번에 연장을 쓸 수 있다.
- 정보 창(0x40b50d 끝·0x40ca6d): 시간 제한이 있을 때만 그린다.
  - 연장 아이콘 다섯 칸(0x106c 찬 칸·0x106b 빈 칸)
  - 남은 초 `%*d` 폭 3, 막대(마지막 60초만 길이), 끝 불꽃 칩
  - 타이머가 꺼져 있으면 숫자·막대 없이 바탕만
- 아이콘 진영(0x476af0): 시작·되살리기 때 사람 진영이 하나면 그 진영, 아니면 없음(0x401d98)이다. 차례 시작마다 차례 진영이 사람이면 그 진영으로 바뀐다(0x40536c).
- TS: 남은 연장 횟수는 BattleWindow가 들고, 저장·자동 저장 블록에 넣는다. 엔진은 바꾸지 않는다. 채팅 기록 문구("%s has run out of time." 등)는 프리 배틀에서 보이지 않아 옮기지 않았다.

  - 레벨 칸 EN_UPDATE는 표 값으로 되돌린다(손으로 바꾼 능력치도 버림).

- 초상: 유닛 그림(마스터, 진영)의 배치표 묶음 0 자세 0x10 가운데 두 열 48 × 67을 색 바꿈 없이 ×2로 그린다. 0x10은 투명이다(0x42cb2a).

## 타이틀·오프닝 동영상(③b-4c-3, `src/ui/title`, 해독 메모 notes_title.md, 픽스처 `title.json`)

- 앱을 열면 프레임이 뜨고 SV080 질문(0x441fd3)이 먼저 나온다. 되살리면 AVI·타이틀이 없다.
- 그 밖이면 0x425fcd다.
  - 화면 전체 검은 팝업(VANTAGEPOPUP, 프레임·메뉴 줄을 덮음) 위에 FALCOM.AVI(Microsoft Video 1 16비트, 158프레임 × 50ms = 7.9초)를 가운데 320 × 240으로 1:1로 튼다. 리메이크는 원본 AVI를 브라우저에서 직접 푼다(`src/formats/avi.ts`, ffmpeg 프레임 MD5 골든과 같음).
  - 왼쪽 클릭이면 건너뛴다. 키·오른쪽 단추는 무시한다.
  - AVI를 끝까지 보면(또는 파일이 없으면) 오프닝 애니메이션(상태 1, 0x426c54)이다. 픽스처 `opening.json`, ③b-4c-4.
    - 엔진(0x4887d8, `src/ui/title/opening/`)을 옮겼다. 7장 + 글 카드 + 로고, 1858틱(89초)이고 틱마다 DIB·색 표가 원작과 같다.
    - 48ms마다 시계(0x43307e)를 돈다. 16ms 카운터는 지난 시간이라 늦게 온 틱은 그리지 않고 스텝을 몰아 돈다(0.96초 넘게 뒤지면 프레임을 건너뜀).
    - 장 사이에 다음 장 그림을 읽으며 246단위(3.9초) 멈춘다(0x433304).
    - 의도적 차이: 원작은 그림 칸 자료를 공용 arena에 두어(0x431a85가 포인터를 되돌림) 글 카드 중 다음 장을 읽으면 칸 0(갈무리)이 덮인다. 따라잡기(뒤진 틱)가 그 뒤 카드를 다시 그리면 원작은 깨진 그림이고, TS는 칸마다 따로 들어 깨끗하다(오라클 변형에서 그 구간 DIB만 다름).
    - 2장(0x434553)이 게임 난수를 4번 쓰고, 앱 시드도 그만큼 나아간다.
    - 끝나면 타이틀 장면(0x439d23)이 계속 플래그를 내려 메뉴(상태 2)가 뜬다. BGM 0은 그대로 이어진다(98초 뒤 무음).
    - 왼쪽 클릭이면 0x426c7c다: 엔진을 타이틀로 건너뛰고(0x433340, 화면 지움) BGM 8, 다음 48ms 틱에 메뉴다.
- 타이틀(0x425fa0·0x426c7c):
  - 768 × 512 그림, 원점은 ((화면 − 768) / 2, (화면 − 512) / 2)(C 나눗셈, 640 × 480이면 음수)이다. 밖은 팔레트 10번 검정이다.
  - 반짝임은 메뉴가 뜬 뒤 200틱(9.6초)마다 25틱이다. 모달 상자 동안은 48ms 콜백이 멈춘다.
  - 메뉴는 마우스 위가 파란 글자이고 소리는 없다. 키보드는 없다.
  - 클릭은 늘 소리 1이다.
    - Scenario: Select Level 0x83(Easy 0·Normal 1, 0x42668b) → Master making(⑤b)
    - Expert: Master making(⑤b)
    - Network: 지원하지 않는다는 안내창(사용자 결정 10, 원작에 없는 영어 문구)
    - Free Battle: 월드
    - Load Data: 이어 하기 → 게임 데이터
    - Quit: 프레임 없는 검은 화면
  - 원작은 어떤 항목도 회색으로 그리지 않는다.
- 타이틀로 돌아올 때(Turn to Title·월드 창 닫기)는 AVI 없이 바로 메뉴다.

## Master making(⑤b, `src/ui/master/makeMaster.ts`·`MasterMaking.tsx`, 픽스처 `makeMaster.json`)

- 48ms 콜백 0x426ff9:
  - 번쩍임이 끝나 있으면 기다리던 다음 스텝(0x427166), 진행 중이면 색 표.

- 스텝: 시나리오 −1, Expert 0x31에서 시작(0x427060).

  - 답(0x42937e: x 220~395, y 300 + 20k) → 카드(4 + 36 + 클릭 + 8 + 8 프레임)
  - 결과(0x42842d: 점수 합 → 0x465f34 마스터, 0x42d190) → 이름 상자
  - 특수 이름(0x428542) → 설명 → 시나리오는 시작 네이티얼 넷 소개 → 끝 → 월드(0x45102d)

- 이름 상자 0x7c(모달리스, 창 가로 가운데·높이 7/8, 0x429496):
  - 처음 글자는 마스터 기본 이름이다.
  - OK는 1~16바이트면 소리 1, 아니면 소리 3이고 상자에 남는다. Esc는 무시한다.
- 창 닫기·Turn to Title(0x44e390 장면 2)은 0x426f81 → 타이틀(0x425fa0)이다.
- 창 팔레트 0x4800e0:
  - 타이틀이 남긴 색 위에 공통 1·0x29·0x2d·섞은 0x86~0xe5(0x42754c)를 읽는다.
  - 질문 때 0x2e·5번 빨강(0x42792c)을 읽는다.
  - 결과 때 0x32~0x5c → 7~0x31, 공통 2(0x42842d)를 읽는다.
  - 틱마다 DIB·색 표·난수가 원작과 같다(세 세션).

## 한국어판(⑤e, `src/i18n`, `original.ts`, 시험 `test/i18n`)

- 자료: `pnpm import-korean <폴더>`가 한국어판 `Vmv2.exe`·DATA00/08/09/10을 `original/KO/`에 들인다. 언어(`vmv2.language`, 화면 크기 옆 select)가 한국어이고 자료가 있으면 한국어로 읽는다. 바꾸면 다시 연다.
- 문자열: 두 exe는 컴파일 설정이 달라 코드가 맞지 않는다. 표의 칸끼리와 뜻으로 짝지은 직접 주소로 영문 VA → 한국어 VA 대응표(`tools/i18n/map_strings.py` → `koStrings.json`, 주소만)를 만든다. 한국어판 링커는 한 함수 안의 글을 거꾸로 놓고 같은 글을 합친다.
- `koreanExe`: 표(수치)는 영문판, cString은 대응표의 한국어판 바이트(CP949, 글자 = 바이트), 리소스(대화 상자·메뉴·아이콘)는 한국어판을 0x40000000 위에 올려 읽는다. 대화 상자·메뉴 글은 UTF-16이라 그대로 한국어다. 메뉴의 System·Window·Save GameData·Customize·Sound, 타이틀 메뉴, 모드 이름은 한국어판도 영문이고, 프레임 제목은 'Vantage Master Tactics V2'다.
- DAT: 한국어판에서 다른 항목은 DATA00 26(안내 그림), 08 0~5(장 사이 장면), 09 0~26(마스터 엔딩), 10 0~89(맵 +0·+0x78·+0x1a0, MAS +0·+0x1c 글 자리만)다. 안내 그림은 같은 그림을 528 폭으로 자른 것이라 영문판을 쓴다.
- HTML 글(창 제목·대화 상자·목록·편집 칸)은 바이트 문자열을 CP949로 풀어 보이고(`htmlText`), 친 글은 CP949 바이트로 바꾼다(`byteText`). 브라우저의 TextDecoder('latin1')는 windows-1252라 바이트를 바꾸므로 이름 같은 바이트 문자열은 String.fromCharCode로 푼다.
- 한국어판이 그리기 자리를 바꾼 곳: 결과 창 소요 시간(일·시·분 x 143·215·242 → 128·160·184, 0x40b5c4·0x40b628·0x40b669), 장면 보고서 쪽 0 소요 시간(x 0x177·0x1c7·0x1e2 → 0x168·0x190·0x1a8, 0x41ce65·0x41cec9·0x41cf2b), 도움말 창 폭. 정보 창·맵 정보·마스터 정보·결과 창 쪽 1~5·보고서의 다른 숫자 자리는 같다.
- 한국어판 exe는 대응표를 만든 빌드(SHA-256 bfdbd88a…)만 읽는다(`koreanImage`, `import-korean`도 확인). 아니거나 열 수 없으면 원문으로 읽는다.

## BGM(③b-5, `src/ui/sound/bgm.ts`·`midiPlayer.ts`, 해독 메모 notes_options.md §3.5, 픽스처 `bgm.json`)

- 곡 표 0x4742f0(19곡: CD 트랙, `MIDI/CR0nnGM.MID`·GS·S8, 반복)이다. 0·4·5·7만 반복하지 않는다.
- 곡을 트는 곳(0x443770):
  - 처음 타이틀(AVI와 함께) 0, 건너뜀·돌아옴 8
  - 월드 1
  - 전투 시작·되살리기는 맵 +0x2c(9~18)
  - 전투 끝·항복은 3 − 이김(이김 2, 짐 3)이고 결과 창 내내 그대로다.
  - 마스터 만들기 6(아직 없음)
- 상태 기계:
  - BGM이 꺼져 있으면 곡 번호만 적는다. 같은 곡을 틀고 있으면 아무것도 하지 않는다.
  - 끝 알림(0x443847): 반복 곡은 처음부터 다시 튼다(곡 전체, 루프 지점 없음). 비반복 곡은 멈추고 곡 번호가 −1이 된다.
  - Sound OK: 장치가 바뀌면 멈춤·CD 닫기, BGM 비트나 장치가 바뀌면 지금 곡을 다시 튼다(0x44372e).
- 장치:
  - MIDI(기본, 결정 9): spessasynth_lib WorkletSynthesizer + Sequencer(skipToFirstNoteOn 끔, 반복 0), 사운드폰트 `original/GeneralUser-GS.sf2`(`pnpm fetch-soundfont`, 다른 SF2·DLS로 바꿀 수 있음), 음량 0.7.
  - CD: 사용자가 준 음원을 `pnpm import-cd-audio <앨범 폴더>`로 `original/CDDA/TRACKnn.mp3`(nn = 표의 CD 트랙 2~20)에 들이면 오디오 요소로 그 트랙을 한 곡 튼다(0x443973). 반복은 끝 알림에 다시 틀기(0x443847). 파일이 없으면 열기 실패(소리 없음). 원작의 "There is no CD audio…" 시작 상자는 없앴다(결정 9).
    - 앨범 'CD Audio/NN'은 데이터 트랙 다음 차례라 NN 01~18 → CD 트랙 NN + 1이고, 트랙 20(엔딩 2, 곡 5)은 V2 판(20번 파일)이다: V2의 CR005GM.MID 길이 392.8초가 V2 판(392.6초)과 맞는다.
  - SC-88(장치 3): 원작은 `MIDI/CR0nnS8.MID`를 MIDI 시퀀서로 틀지만 이 데이터에 없다. TS는 앨범 'SC-88' 녹음(21~38 → CD 트랙 2~19, 40 → 20)을 같은 스크립트로 `original/SC88/TRACKnn.mp3`에 들여 CD와 같은 방식으로 튼다. 반복은 끝 알림에 replay.
  - GS(장치 2): 파일이 없어 고를 수 없다. 저장한 장치가 GS면 MIDI로(0x44369a).
  - 파일·사운드폰트가 없으면 오류 없이 소리만 없다(MCI 열기 실패처럼).
- 브라우저 자동 재생 제한: AudioContext는 첫 사용자 동작에 깨운다.
